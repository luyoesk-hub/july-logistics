## 5. 데이터 정리 정책

### 5.1 필수 필드 정책

**접수 시점에 반드시 입력해야 하는 필드:**

1. **보내는 분 이름** - 텍스트, 최대 20자
2. **받는 분 이름** - 텍스트, 최대 20자
3. **받는 분 전화번호** - `010-0000-0000` 형식, 필수
4. **도착 시·도** - 드롭다운 (17개 지역 고정)
5. **물품명** - 텍스트, 최대 50자
6. **무게** - 숫자, 0.1 ~ 25kg
7. **가로·세로·높이** - 숫자, 1 ~ 160cm

### 5.2 자동 계산 필드 정책

**시스템이 자동으로 계산하는 필드 (사용자 입력 불가):**

1. **세 변의 합** = 가로 + 세로 + 높이
2. **부피 무게** = (가로 × 세로 × 높이) / 6000
3. **요금 무게** = MAX(실제 무게, 부피 무게)
4. **크기 등급** - 세 변의 합과 무게 기준
   - 극소형: 세 변 60cm 이하, 무게 2kg 이하
   - 소형: 세 변 80cm 이하, 무게 5kg 이하
   - 중형: 세 변 120cm 이하, 무게 15kg 이하
   - 대형: 세 변 160cm 이하, 무게 25kg 이하
   - 초과: 접수 불가
5. **배송 요금** - 크기 등급 + 권역별 요금표 적용
6. **도착 예정일** - 접수일 + 권역별 소요일 (영업일 기준)

### 5.3 권역별 배송 규정

| 권역 | 해당 지역 | 소요일 | 요금 예시(극소형) |
|------|----------|--------|-----------------|
| **일반** | 제주·도서산간 제외 전국 | 다음 영업일 | 3,500원 |
| **제주** | 제주도 전역 | 2영업일 | 6,500원 |
| **도서산간** | 울릉도, 백령도, 흑산도 등 | 3영업일 | 8,500원 |

### 5.4 금지 품목 정책

**다음 물품은 접수 단계에서 자동 거절:**

| 분류 | 금지 품목 |
|------|----------|
| 금전 | 현금, 상품권, 유가증권 |
| 귀중품 | 금, 은, 보석, 시계(50만원 초과) |
| 인화성 | 라이터, 부탄가스, 페인트, 신나, 알코올 스프레이 |
| 배터리 | 보조배터리, 리튬배터리 단품 |
| 생물 | 살아있는 동물, 살아있는 식물 |
| 온도민감 | 냉장·냉동이 필요한 식품 |
| 기타 | 주류, 의약품, 총포·도검 |

## 6. 시스템 운영 정책

### 6.1 접수 화면 운영

**배포 위치:**
- 웹: https://july-logistics.vercel.app
- GitHub Pages: https://luyoesk-hub.github.io/july-logistics

**접근 권한:**
- 내부: 모든 접수 담당자
- 외부: 제한 없음 (웹 공개)

**운영 시간:**
- 평일 09:00 ~ 18:00 (토일 제외)
- 비상 상황: 경영진 판단

### 6.2 데이터 입력 표준

**날짜 형식:**
- 표준: `YYYY-MM-DD HH:MM:SS` (예: 2026-08-06 14:30:00)
- 입력 방식: 시스템 자동 기입 (사용자 선택)

**전화번호 형식:**
- 표준: `010-0000-0000` (하이픈 포함)
- 검증: 11자리 숫자 + 하이픈 패턴 강제

**이름 입력:**
- Trim 처리: 앞뒤 공백 자동 제거
- 메모 분리: "(직접수령)" 같은 주석 제거 (필요시 별도 필드로)

### 6.3 데이터 검증 규칙

**입력 시점 검증:**
1. 필수 필드 입력 확인
2. 형식 검증 (전화번호, 이메일 등)
3. 범위 검증 (무게, 치수)
4. 금지 품목 자동 검사
5. 크기 등급 초과 시 접수 거절

**저장 시점 검증:**
1. 운송장 번호 고유성 확인
2. 고객 정보 존재 확인
3. 요금 계산 결과 검증
4. 도착 예정일 논리성 확인

### 6.4 에러 처리

**시스템 에러:**
- 500 에러 → 관리자 알림 + 사용자 재시도 안내
- 데이터베이스 오류 → 자동 로깅 + 경영진 알림

**데이터 에러:**
- 필수 필드 누락 → 사용자 입력 요청
- 형식 오류 → 자동 수정 또는 입력 거절
- 논리 오류 → 관리자 수동 검토

## 11. 비상 대응 계획

### 11.1 장애 시나리오

**Scenario 1: 요금 계산 오류**
- 발생: 입력 데이터 검증 로직 버그
- 대응: 즉시 서비스 중단 → 버그 수정 → 재배포
- 예방: 정기 요금 표 검증 (월 1회)

**Scenario 2: 운송장 번호 중복**
- 발생: DB 제약 조건 미설정
- 대응: 중복 제거 + 시스템 보정
- 예방: 시스템 레벨 고유성 강제

**Scenario 3: 데이터 베이스 손상**
- 발생: 하드웨어/소프트웨어 장애
- 대응: 최근 백업본으로 복구 (3일 손실 가능)
- 예방: 일일 자동 백업 (미적용 → TODO)

### 11.2 비상 연락처

- **IT 담당자**: 즉시 호출
- **경영진**: 1시간 이상 장애 시
