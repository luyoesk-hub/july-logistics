# Phase 4 설계: CSV 대량 배송 업로드

> 여러 건을 한 번에 접수하는 기능

---

## 📊 기능 개요

### 목적
```
반복적인 수작업 입력 제거
여러 건을 CSV로 업로드 → 자동 검증 → 일괄 접수
```

### 사용 사례
```
1. 아침에 주문 30건 일괄 접수
2. 지점별 정기 배송 자동화
3. 엑셀에서 CSV 내보내기 → 드래그&드롭
```

### 예상 효과
```
입력 시간: 30건 × 2분 = 60분 → 5분 (10배 개선)
오류율: 수동 입력 오류 제거
```

## 🏗️ 아키텍처

### 사용자 흐름

```
1. CSV 파일 선택/드래그
     ⬇
2. 파일 파싱 (PapaParse)
     ⬇
3. 필드 매핑 (어느 컬럼이 뭔지 선택)
     ⬇
4. 데이터 검증 (행별로)
     ├─ 필수 값 확인
     ├─ 금지 품목 검사
     └─ 한도초과 검사
     ⬇
5. 미리보기 (처리될 데이터)
     ├─ ✅ 성공: 초록색
     ├─ ⚠️ 경고: 노란색
     └─ ❌ 오류: 빨간색
     ⬇
6. 최종 승인
     ⬇
7. 일괄 접수 실행
     ├─ 진행률 표시
     └─ 완료 리포트
     ⬇
8. 목록 자동 갱신
```

## 📋 CSV 포맷 설계

### 필수 컬럼 (6개)

```
┌────────────────┬──────────────────┬────────────────┐
│ 컬럼명         │ 데이터 타입      │ 예시           │
├────────────────┼──────────────────┼────────────────┤
│ sender_name    │ 텍스트           │ 김민준         │
│ receiver_name  │ 텍스트           │ 이서연         │
│ receiver_area  │ 텍스트           │ 서울           │
│ item_name      │ 텍스트           │ 이불           │
│ weight_kg      │ 숫자             │ 3.0            │
│ dimensions     │ 텍스트 (W×H×D)   │ 60x40x50       │
└────────────────┴──────────────────┴────────────────┘
```

### 선택 컬럼 (3개, 있으면 활용)

```
┌──────────────────┬──────────────┬──────────┐
│ 컬럼명           │ 데이터 타입  │ 기본값   │
├──────────────────┼──────────────┼──────────┤
│ branch           │ 텍스트       │ 입력값   │
│ shipping_option  │ 텍스트       │ standard │
│ memo             │ 텍스트       │ -        │
└──────────────────┴──────────────┴──────────┘
```

### CSV 샘플 파일

```csv
sender_name,receiver_name,receiver_area,item_name,weight_kg,dimensions,branch,shipping_option
김민준,이서연,서울,이불,3.0,60x40x50,서울지점,standard
박준호,최지운,부산,책,12.0,30x20x20,서울지점,standard
이순신,유민준,인천,화장품,1.5,20x15x10,용산지점,express
한승윤,김지호,대전,운동화,2.0,35x25x20,대전지점,overnight
...
```

## 🔍 검증 로직

### 단계별 검증

#### 1단계: 필드 존재 확인
```javascript
필수 필드 체크:
✅ sender_name 존재
✅ receiver_name 존재
✅ receiver_area 존재
✅ item_name 존재
✅ weight_kg 존재 (숫자)
✅ dimensions 존재 (W×H×D 형식)

실패 시:
❌ "필수 필드 누락: sender_name"
```

#### 2단계: 데이터 타입 검증
```javascript
✅ weight_kg: 숫자이고 > 0
✅ dimensions: "60x40x50" 형식 (숫자x숫자x숫자)
✅ shipping_option: standard/express/overnight 중 하나

실패 시:
❌ "weight_kg 값이 잘못됨: abc (숫자 필요)"
```

#### 3단계: 규정 검증
```javascript
✅ 금지 품목 검사 (item_name)
✅ 크기/무게 한도 검사
  - 세변합 160cm 이하
  - 요금무게 25kg 이하

경고 시:
⚠️ "라이터: 접수 불가 품목"
```

#### 4단계: 자동 계산
```javascript
// 각 행마다 자동 계산:
① 부피 무게
② 요금 무게 (실제 vs 부피)
③ 크기 등급
④ 권역 (도착지역으로)
⑤ 기본 요금
⑥ 최종 요금 (배송옵션 적용)
⑦ 도착예정일
⑧ 운송장 번호 (자동 할당)
```

## ⚠️ 고려사항

### 1. 파일 크기 제한
```javascript
const MAX_FILE_SIZE = 5 * 1024 * 1024; // 5MB

if (file.size > MAX_FILE_SIZE) {
  alert('파일이 너무 큽니다 (최대 5MB)');
}
```

### 2. 메모리 부하
```
1,000건 업로드 시 메모리: ~10MB
브라우저 처리: 2-3초 (지연 가능)
해결책: 배치 처리 (100건씩)
```

### 3. 운송장 번호 충돌
```
기존: 1100000001
새로: 1100000002 (자동 증분)
중복 체크: issuedTrackingNos Set 사용
```

### 4. 오류 복구
```
일부 실패 시:
- 실패한 행만 제외
- 성공한 행은 접수 완료
- 오류 리포트 제공 (재시도 가능)
```
