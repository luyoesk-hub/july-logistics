## 🧪 테스트 1: 기본 접수 기능 (Phase 1)

### 1-1. 접수 입력 폼

```
테스트: 6대 필수 입력 필드 확인
✅ 접수 지점 입력 필드
✅ 보내는 분 이름 입력 필드
✅ 받는 분 이름 입력 필드
✅ 도착 지역 입력 필드
✅ 배송 옵션 라디오 버튼 (3개)
✅ 물품명 입력 필드
✅ 실제 무게 숫자 입력
✅ 가로/세로/높이 숫자 입력

예상 결과:
모든 필드가 보이고 입력 가능해야 함
```

### 1-2. 기본 요금 계산 (스탠다드)

```
입력값:
- 지점: 서울지점
- 보내는 분: 김민준
- 받는 분: 이서연
- 도착지역: 서울
- 물품명: 이불
- 무게: 3.0 kg
- 크기: 60 × 40 × 50 cm
- 배송옵션: 스탠다드 (기본)

우측 계산 과정 확인:
✅ 부피 무게: 60 × 40 × 50 / 6000 = 20kg
✅ 요금 무게: max(3, 20) = 20kg
✅ 세 변의 합: 60 + 40 + 50 = 150cm
✅ 크기 등급: 대형 (통과)
✅ 권역: 일반
✅ 기본 요금: 9,000원
✅ 배송옵션: 스탠다드 (배송옵션 요금 없음)
✅ 도착예정일: 다음 영업일 (토일 제외)

최종 결과:
✅ 접수 완료 버튼 활성화
✅ 운송장: 1100000001 생성
✅ 요금: 9,000원

테스트 통과: ✅ / ❌
```

### 1-3. 금지 품목 검사

```
입력값: 물품명 = "라이터"

예상 결과:
✅ 빨간 배지: "접수 불가 품목 - 인화성"
✅ 계산 과정 정지 (단계 1에서 중단)
✅ 접수 완료 버튼 DISABLED

테스트 통과: ✅ / ❌
```

### 1-4. 한도초과 검사

```
입력값:
- 물품명: 커튼
- 무게: 3.8 kg
- 크기: 64 × 53 × 47 cm

계산:
- 부피 무게: 64 × 53 × 47 / 6000 = 100.96kg (초과)
- 세 변의 합: 164cm (초과)

예상 결과:
✅ 에러 메시지: "대형 상한 초과"
✅ 접수 완료 버튼 DISABLED

테스트 통과: ✅ / ❌
```

## 🧪 테스트 2: 배송 옵션 (Phase 2)

### 2-1. 배송 옵션 UI

```
위치: 도착지역 아래
확인 사항:
✅ 스탠다드 카드 (기본값, 선택됨)
✅ 익스프레스 카드 (+1일 빠름, +20%)
✅ 나이트 카드 (+50%, 다음날)
✅ 각 카드는 라디오 버튼과 클릭 영역

테스트 통과: ✅ / ❌
```

### 2-2. 익스프레스 선택

```
같은 이불 패키지, 익스프레스 선택

우측 계산 과정:
✅ 단계 6: 기본 요금 9,000원
✅ 단계 7: 익스프레스 요금 = 9,000 × 1.2 = 10,800원
✅ 단계 8: 도착예정일이 1일 앞당겨짐 (오늘 등록 → 내일 도착)

최종 결과:
✅ 운송장: 1100000002 (새 번호)
✅ 요금: 10,800원
✅ 배송옵션: 익스프레스 (영수증에 표시)

테스트 통과: ✅ / ❌
```

### 2-3. 나이트 선택

```
같은 이불 패키지, 나이트 선택

예상 결과:
✅ 요금: 9,000 × 1.5 = 13,500원
✅ 도착예정일: 2일 빨라짐 (확인 필요)

테스트 통과: ✅ / ❌
```

## 🧪 테스트 3: 주소록 (Phase 2-3)

### 3-1. 주소 저장

```
1단계: 첫 배송 입력
- 보내는 분: 김민준
- 도착지역: 서울
- "저장" 버튼 클릭

예상 결과:
✅ 알림: "저장됐습니다: 김민준 → 서울"
✅ 드롭다운에 항목 추가

테스트 통과: ✅ / ❌
```

### 3-2. 주소 5개 저장

```
5건을 순차적으로 저장:
1. 김민준 → 서울
2. 이서연 → 부산
3. 박준호 → 인천
4. 최지운 → 대구
5. 유민준 → 광주

예상 결과:
✅ 드롭다운에 5개 모두 표시
✅ 6번째 저장 시 가장 오래된 항목 제거

테스트 통과: ✅ / ❌
```

### 3-3. 빠른 선택

```
드롭다운에서 "김민준 → 서울" 선택

예상 결과:
✅ 보내는 분 자동 채우기: "김민준"
✅ 도착지역 자동 채우기: "서울"
✅ 받는 분, 물품명 등은 빈 상태 유지
✅ 드롭다운 초기화

테스트 통과: ✅ / ❌
```

### 3-4. 주소록 관리 (Phase 3)

```
1. "📋 주소록 관리" 버튼 클릭

예상 결과:
✅ 모달 열림
✅ 저장된 주소 5개 나열
✅ 각 항목 옆에 "삭제" 버튼
✅ 카운트: "5/20"

2. "김민준 → 서울" 삭제 클릭

예상 결과:
✅ 확인 메시지 표시
✅ OK 클릭 후 목록에서 제거
✅ 드롭다운도 갱신

3. "모두 삭제" 클릭

예상 결과:
✅ 확인 메시지: "되돌릴 수 없습니다"
✅ 모든 항목 제거
✅ 카운트: "0/20"

테스트 통과: ✅ / ❌
```

### 3-5. 페이지 새로고침 후 주소록 유지

```
1. 주소 3개 저장
2. 페이지 새로고침 (F5 또는 Ctrl+R)

예상 결과:
✅ 새로고침 후에도 3개 주소 유지
✅ localStorage에 저장됨 (개발자 도구 확인 가능)

테스트 통과: ✅ / ❌
```

## 🧪 테스트 4: 목록 및 조회 (Tab 2)

### 4-1. 목록 테이블

```
5건 이상 접수 후 "목록 및 조회" 탭 클릭

확인 사항:
✅ 테이블 렌더링 (모든 컬럼 보임)
✅ 운송장, 지점, 보낸이, 받는이 정확한지
✅ 배송옵션 컬럼 표시 (Phase 2 추가)
✅ 요금 = 최종 요금 (배송옵션 적용)

예시:
┌──────────┬──────┬────────┬──────────┬──────────┐
│ 운송장   │ 지점 │ 보낸이 │ 배송옵션 │ 요금     │
├──────────┼──────┼────────┼──────────┼──────────┤
│1100000001│서울  │김민준  │스탠다드  │ 9,000원  │
│1100000002│서울  │김민준  │익스프레스│10,800원  │
└──────────┴──────┴────────┴──────────┴──────────┘

테스트 통과: ✅ / ❌
```

## 🧪 테스트 5: 통계 (Tab 3)

```

카드 1 - 전체 접수: 10
카드 2 - 총 요금: (요금 합계)
카드 3 - 평균 요금: (합계 / 10)
카드 4 - 접수 거절: (금지품목 + 한도초과)

예상 결과:
✅ 4개 카드 모두 표시
✅ 숫자 정확한지 확인

테스트 통과: ✅ / ❌

### 5-2. 지점별 통계

```

✅ 각 지점별 건수
✅ 각 지점별 총 요금
✅ 각 지점별 평균 요금
✅ 가장 많은 권역 표시

## 🧪 테스트 6: 규정 준수 검증

### 6-1. 운송장 번호

```
5건 접수 후 운송장 확인:
- 지점코드 2자리 (11, 12, 21, 31, 32, 41 중 하나)
- 순번 8자리 (00000001 ~ 99999999)

예상 결과:
✅ 1100000001 (서울)
✅ 1200000001 (용산)
✅ 2100000001 (대전)
✅ 등 모두 10자리
✅ 같은 번호 중복 없음

테스트 통과: ✅ / ❌
```

### 6-2. 권역 판정

```
입력값: 도착지역 = "제주"

예상 결과:
✅ 자동 판정: 제주 권역
✅ 제주 요금 적용 (일반보다 비싼 요금)
✅ 도착예정일: 2영업일

입력값: 도착지역 = "거제"

예상 결과:
✅ 자동 판정: 일반 권역 (도서산간 아님!)
✅ 일반 요금 적용

테스트 통과: ✅ / ❌
```

### 6-3. 부피 무게 & 요금 무게

```
입력값:
- 실제 무게: 2kg
- 크기: 40 × 30 × 60cm

계산:
- 부피 무게: 40 × 30 × 60 / 6000 = 12kg
- 요금 무게: max(2, 12) = 12kg ← 큰 값 선택

예상 결과:
✅ 계산 과정에 12kg로 표시
✅ 12kg로 요금 계산

테스트 통과: ✅ / ❌
```

### 6-4. 크기 등급 판정

```
입력값 1: 세변합 70cm, 요금무게 6kg
예상: 소형 기준 초과 → 중형 (80cm/5kg 초과)

입력값 2: 세변합 150cm, 요금무게 20kg
예상: 대형 (160cm/25kg 이하)

테스트 통과: ✅ / ❌
```
